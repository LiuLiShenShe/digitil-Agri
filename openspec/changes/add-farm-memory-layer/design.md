## Context

当前平台已有 IoT 模拟链路、告警和监控大屏，但数据尚未稳定地围绕农业对象组织。PRD 推荐建立“状态与记忆层”，让状态实时或日级同步，几何按阶段更新，日报按对象聚合。

## Goals / Non-Goals

**Goals:**

- 按农业对象组织最新值、趋势、聚合、事件和日级归档。
- 支持 24 小时和 7 天查询窗口。
- 支持温室日报引用同一温室的环境、设备、告警和事件数据。
- 为 TimeSeriesAgent、GrowthAnalysisAgent、AlertDiagnosisAgent 和 ReportAgent 提供受控只读数据源。

**Non-Goals:**

- 不在本变更中完成真实设备生产级接入。
- 不实现任意复杂 BI 分析。
- 不让 Agent 直接控制设备。
- 不要求每日植株 GLB 重建。

## Decisions

- 同步频率作为对象或对象类型策略保存，支持 realtime、hourly、daily、milestone、static。
- 指标字典先覆盖温室 MVP 常见环境、土壤、水质、灌溉和设备状态指标。
- 事件层采用统一事件模型，事件类型覆盖灌溉、施肥、告警、巡检、维护和 Agent 分析记录。
- 查询接口以对象 ID 和时间范围为主，避免前端和 Agent 直接拼接数据源细节。
- 日级归档与原始时序分层，保证日报生成稳定且成本可控。

## Risks / Trade-offs

- 若只保留最新值，日报和告警解释缺少依据；若保留过细原始数据，演示系统成本上升。本设计保留最新值、常用窗口和日级归档的折中。
- 模拟数据必须带数据质量状态，避免与真实设备数据混淆。
- 指标字典需要逐步治理单位和采样频率，否则不同页面和 Agent 输出会不一致。
