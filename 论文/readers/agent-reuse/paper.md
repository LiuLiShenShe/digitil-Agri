## Abstract

<a id="A001"></a>
**Source:** p.2706 Abs-En

**原文 (Original English):** Integrating large language models (LLMs) into personal assistants, like Xiao Ai and Blue Heart V, effectively enhances their ability to interact with humans, solve complex tasks, and manage IoT devices. Such assistants are also termed LLM-driven agents. Upon receiving user requests, the LLM-driven agent generates plans using an LLM, executes these plans through various tools, and then returns the response to the user. During this process, the latency for generating a plan with an LLM can reach tens of seconds, significantly degrading user experience. Real-world dataset analysis shows that about 30% of the requests received by LLM-driven agents are identical or similar, which allows the reuse of previously generated plans to reduce latency. However, it is difficult to accurately define the similarity between the request texts received by the LLM-driven agent through directly evaluating the original request texts. Moreover, the diverse expressions of natural language and the unstructured format of plan texts make implementing plan reuse challenging. To address these issues, we present and implement a plan reuse mechanism for LLM-driven agents called AgentReuse. AgentReuse leverages the similarities and differences among requests' semantics and uses intent classification to evaluate the similarities between requests and enable the reuse of plans. Experimental results based on a real-world dataset demonstrate that AgentReuse achieves a 93% effective plan reuse rate, an F1 score of 0.9718, and an accuracy of 0.9459 in evaluating request similarities, reducing latency by 93.12% compared with baselines without using the reuse mechanism.

**Keywords:** artificial intelligence of things; large language models (LLMs); agent; semantic cache; similarity evaluation

Therefore, the plan steps generated by the agent should be the same; only the specific key parameters "time, departure location, destination" differ. That is, Request 2 should be judged as similar to Request 1, and Request 2 should not directly receive Request 1's response; rather, Request 2 should reuse the plan that the LLM generated for Request 1.

### 6.2 多意图分类与基于屏幕理解的智能体 (Multi-Intent Classification and Screen-Understanding-Based Agents)

<a id="S601"></a>
**Source:** p.2717 S601

**原文 (Original Chinese):** 本文的主要研究对象是大模型驱动的智能体，具体来说是大模型驱动的智能物联网应用，如小米公司的小爱同学、OPPO公司的小布助手等. 传统上，一般用户只会对智能体产生1个输入，如"帮我预定后天合肥到北京的票". 现今，随着社会的发展，智能汽车逐渐走入千家万户，智能汽车上的组件更多，此时，用户的1句话中可能包含多个任务，如"右前侧车窗降低，左后侧车窗抬高，打开雨刷器，播放陶喆的音乐". 此时，需要采用多意图分类模型对文本中的意图进行分类和参数识别，分类后，将1句话分割为多个部分，再并行使用AgentReuse机制进行复用即可. 但当句子间有因果关系时，如"如果室内温度超过28摄氏度，就把空调开到制冷26摄氏度"，就不能简单地将句子分割为多个部分，需要引入新的模型对有因果关系的句子进行处理，经处理后再利用AgentReuse对之前生成的计划进行复用.

**English:** The main research subject of this paper is LLM-driven agents, specifically LLM-driven AIoT applications such as Xiaomi's Xiao Ai Classmate and OPPO's Xiao Bu Assistant. Traditionally, users generally provide only one input to the agent, such as "Help me book a ticket from Hefei to Beijing for the day after tomorrow." Nowadays, with societal development, smart cars are gradually entering millions of households, and smart cars have more components. At this point, a user's single sentence may contain multiple tasks, such as "Lower the right front window, raise the left rear window, turn on the wipers, play David Tao's music." In such cases, a multi-intent classification model is needed to classify the intents in the text and identify parameters. After classification, the single sentence is segmented into multiple parts, and the AgentReuse mechanism can then be used in parallel for reuse. However, when there are causal relationships between sentences, such as "If the indoor temperature exceeds 28 degrees Celsius, set the air conditioner to cooling at 26 degrees Celsius," the sentence cannot simply be segmented into multiple parts. A new model needs to be introduced to process sentences with causal relationships; after processing, AgentReuse can then be used to reuse previously generated plans.

## 7 结论 (Conclusion)

## 阅读提示 (Reading Notes)

### 论文核心贡献

本文提出了 **AgentReuse**，一种面向大模型驱动的智能体的计划复用机制。核心思想是：智能体接收到用户请求后，不是直接调用大模型生成新计划，而是先通过意图分类和关键参数提取来判断是否可以复用之前已缓存的计划。

### 关键创新点

1. **语义差异性利用**：不再直接比较原始请求文本的相似度，而是先提取关键参数（时间、地点等），用去掉参数后的"意图模板"进行相似性匹配。
2. **计划而非响应的复用**：由于机票等信息实时变化，复用计划（而非最终响应）更合理，只需替换参数后重新执行。
3. **结构化计划表示**：通过提示工程让大模型生成带依赖标注的结构化计划，解决了非结构化文本难以有效复用的问题。
4. **意图内检索**：将相似性搜索限制在当前意图类别内，显著降低了搜索空间和延迟。

### 阅读时需注意

- 第3节（算法1）是理解整个系统的关键，建议结合第2节的数学形式化和第3节的例子一起阅读。
- 实验部分（第5节）中，表1和图4是核心结果，显示了AgentReuse相对于GPTCache和MeanCache的优势。
- 额外代价分析（5.4节）表明意图分类模型可"借"用个人助手已有的模型，因此实际额外代价更低。

### 与其他工作的关系

本文与[16] GPTCache和[14] MeanCache直接对比，后两者针对的是LLM响应的缓存复用，而本文首次提出了面向智能体计划的缓存复用。本文的"计划复用"概念可以看作是语义缓存在智能体场景下的推广。
