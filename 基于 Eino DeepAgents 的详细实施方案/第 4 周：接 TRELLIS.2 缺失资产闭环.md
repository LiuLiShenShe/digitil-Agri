# 第 4 周：接 TRELLIS.2 缺失资产闭环

## 1. 本周目标

把“缺模型就失败”改成“缺模型就进入生成闭环”。
这一周的重点是把 TRELLIS.2 接成平台的缺失资产补齐模块，让系统能在没有现成 GLB 时继续往前走。

## 2. 本周范围

- 根据语义规划结果识别缺失资产。
- 创建 TRELLIS.2 生成任务。
- 记录任务状态、进度、失败原因。
- 生成完成后回写个人模型库或待审核库。
- 前端支持占位模型替换。
- 不追求所有资产都自动生成成功，先保证流程闭环。

## 3. 具体任务

### 3.1 增加缺失资产识别

在 `ScenePlan` 或布局校验阶段标记：

- 哪些对象没有现成 GLB
- 哪些对象只有近似模型
- 哪些对象必须生成新资产

输出 `missingAssets[]`，并附上：

- 资产名
- 提示词
- fallback 分类

### 3.2 设计资产生成任务表

新增资产任务记录：

- 任务 ID
- 提示词
- 原始图片 / 参考图
- 状态：`queued / running / completed / failed`
- 结果 URL
- 缩略图 URL
- 文件大小
- 所属用户
- 审核状态

### 3.3 接入 TRELLIS.2 worker

新增一个独立生成 worker，流程大致是：

1. 领取任务
2. 调用 TRELLIS.2
3. 生成 GLB
4. 生成缩略图
5. 上传到静态资产存储
6. 回写任务状态

### 3.4 前端增加任务状态和替换能力

在模型库或 AI 搭建面板里增加：

- 任务列表
- 生成中状态
- 失败重试
- 成功后替换占位模型

这样用户可以看到“生成中”，而不是只看到一个报错。

### 3.5 资产入库策略

建议分两层：

- 个人待审库：普通用户生成后先进入这里
- 公共模型库：管理员审核后再公开

这样可以避免未审核资产直接污染公共场景。

## 4. 产出物

- `missingAssets` 识别逻辑
- TRELLIS.2 生成任务表
- worker 处理流程
- 前端任务列表和替换入口
- 个人待审 / 公共模型库闭环

## 5. 验收标准

- 缺少模型时不会直接失败。
- 能自动创建生成任务。
- 任务状态可查询。
- 生成完成后能回写模型库。
- 前端能替换占位模型并继续保存场景。

## 6. 风险与处理

- 风险：TRELLIS.2 生成时间长。  
  处理：任务异步化，前端轮询状态。

- 风险：生成质量波动。  
  处理：先接个人待审库，再由管理员审核。

- 风险：GPU 环境不稳定。  
  处理：保留失败重试和降级占位模型。
