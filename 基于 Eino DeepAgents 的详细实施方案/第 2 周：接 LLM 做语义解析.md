# 第 2 周：接 LLM 做语义解析

## 1. 本周目标

把第一周的“关键词规则识别”升级成“LLM 语义解析”。
这一周仍然不接 Eino，但要让用户说得更自然，系统能更稳地理解同义表达、长句描述和组合需求。

## 2. 本周范围

- 让 LLM 直接输出 `ScenePlan`，而不是输出散文。
- 保留规则布局器，不让 LLM 直接决定最终坐标。
- 支持同义词，例如“温室 / 大棚 / 玻璃房”。
- 支持基础上下文，例如当前场景名、已有对象摘要。
- 不接 Eino，不接 TRELLIS.2，不做正式多 Agent 编排。

## 3. 具体任务

### 3.1 设计 LLM Prompt

把目标改成“结构化输出”：

- 只输出 JSON
- 输出字段必须符合 `ScenePlan`
- 缺失资产放入 `missingAssets`
- 不确定时给 `warnings`
- 不能直接输出最终场景保存指令

### 3.2 增加 JSON Schema 校验

解析 LLM 输出时，必须做：

1. JSON 反序列化
2. schema 校验
3. 字段补全
4. 坐标/数量合法性检查

如果输出不合法：

- 重试一次
- 再失败就降级到规则版

### 3.3 注入模型库摘要

把模型库摘要喂给 LLM，至少包括：

- `assetKey`
- 中文名
- 别名
- 分类
- 默认缩放
- 占地尺寸

这样 LLM 才知道“温室”要映射到哪个模型。

### 3.4 支持当前场景上下文

新增一个轻量上下文输入：

- 当前场景名
- 当前已有对象摘要
- 当前选中对象
- 当前是否为“补全场景”模式

这样用户说“继续补几个摄像头”，系统不会误判成新建场景。

### 3.5 做一组语义测试集

准备至少 20 条自然语言样本，覆盖：

- 同义词
- 方位词
- 数量词
- 补全场景
- 模板场景
- 模糊指令

例如：

- “搭一个温室园区”
- “搭一个大棚园区”
- “搭一个玻璃房园区”
- “在左边放 3 个温室”

### 3.6 前端增加解析结果可视化

前端面板里展示：

- 当前生成的对象清单
- 缺失资产列表
- 解析警告
- 当前使用的模型来源

这样用户能看懂系统为什么这样搭。

## 4. 产出物

- LLM 版 `ScenePlan` 解析器
- JSON schema 校验逻辑
- 模型库摘要 prompt
- 20 条语义测试集
- 前端结果可视化

## 5. 验收标准

- “温室 / 大棚 / 玻璃房”能映射到同一类资产。
- 长句描述可以拆成对象、数量、方位和关系。
- 不合法 JSON 能被拦住，不会直接污染场景。
- LLM 失败时能自动回退到规则版。

## 6. 风险与处理

- 风险：LLM 输出格式不稳定。  
  处理：加 schema 校验 + 重试 + 回退。

- 风险：上下文太多导致输出跑偏。  
  处理：只给摘要，不把全场景塞给模型。

- 风险：同义词覆盖不全。  
  处理：不断扩充别名词典和测试集。
