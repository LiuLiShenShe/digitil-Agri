# 智慧农业数字孪生平台 — 建设方案

## 一、项目定位

基于现有数字孪生编辑器，升级为**智慧农业园区搭建平台**。用户可像搭积木一样，从模型库拖拽/选择农田、温室、设备、植物等组件，在 3D 场景中自由布置，并接入数据指标和 IoT 监控，构建完整的智慧农业数字孪生系统。

## 四、分阶段推进计划

### Phase 1：模型资产库扩充（1-2 周）

**目标**：模型库从 17 个扩展到 80+ 个，覆盖农业场景基础组件

| 任务 | 详细 | 产出 |
|------|------|------|
| 批量下载 CC0 模型 | 从 Quaternius / Kenney / Poly Haven 拉取 GLB | 40+ 个 .glb 文件 |
| 模型分类入库 | 扩展 `model` 树：地形、建筑、温室、设备、植物、装饰 | 新的模型树结构 |
| TRELLIS.2 农业定制 | 用农业图片批量生成：蔬菜、果树、农具等 | 20+ 个 AI 生成模型 |
| 模型预览缩略图 | 每个模型自动生成缩略图 | 模型库可视化 |
| 模型元数据 | 为每个模型标注尺寸、分类、标签 | JSON 元数据文件 |

### Phase 2：场景编辑器增强（2-3 周）

**目标**：支持拖拽式搭建智慧农业园区

| 任务 | 详细 | 产出 |
|------|------|------|
| 地形导入 | 支持导入高度图/GeoJSON 生成地形 mesh | 地形高程可视化 |
| 模型分组管理 | 场景中模型支持图层/分组 | 图层管理器 |
| 批量操作 | 框选、批量移动/旋转/缩放/复制 | 生产力提升 |
| 对齐吸附 | 模型拖拽时网格吸附、模型间对齐 | 积木式搭建体验 |
| 场景模板 | 预设场景模板：标准温室、示范田、综合园区 | 3 个默认模板 |
| 地形纹理刷 | 在地面上刷不同的地面纹理（泥土、水泥、草地） | 地面编辑器 |

### Phase 3：数据可视化组件库（2-3 周）

**目标**：在 3D 场景中嵌入 2D/3D 数据图表

| 任务 | 详细 | 产出 |
|------|------|------|
| ECharts 3D 集成 | 将 ECharts 图表渲染到 Three.js 纹理/平面 | 柱状图、折线图、饼图 |
| 3D 柱状图 | Three.js 原生柱状图（用于产量/能耗对比） | 3D 数据柱 |
| 热力图 | Canvas 热力图叠加到地形上 | 土壤温度/湿度热力 |
| 雷达图 | 环境综合评分雷达图面板 | 气象雷达图 |
| 数据面板组件 | 在场景中放置可交互的数据面板 | 悬浮/固定数据面板 |
| 实时数据刷新 | 前后端 WebSocket 推送 | 数据推送通道 |

### Phase 4：IoT 与监控接入（2-3 周）

**目标**：真实/模拟 IoT 数据驱动场景变化

| 任务 | 详细 | 产出 |
|------|------|------|
| MQTT 适配器 | Go 后端订阅 MQTT Topic，解析 IoT 数据 | MQTT 数据通道 |
| 设备模型数据绑定 | 模型与 IoT 设备 ID 关联，实时状态映射 | 设备状态联动 |
| 传感器可视化 | 温度/湿度/光照数值在 3D 场景中浮空显示 | 数据标注点 |
| 告警系统 | 阈值触发告警，模型颜色变化/闪烁 | 告警状态机 |
| 摄像头视频流 | 将 RTSP/WebRTC 视频流映射到 3D 场景中的屏幕模型 | 视频监控面板 |
| 模拟数据生成器 | 开发用模拟 IoT 数据（温度、湿度、土壤、水位等） | 演示用数据源 |

### Phase 5：业务子系统（3-4 周）

**目标**：在 Phase 4 的 IoT 数据、告警、视频流基础上，沉淀可巡检、可联动、可演示的农业业务闭环，覆盖土壤墒情、气象监测、水肥灌溉、大棚控制、视频监控、环境监测 6 个子系统。

#### 5.0 统一业务底座

| 任务 | 详细 | 产出 |
|------|------|------|
| 业务对象建模 | 定义地块、温室、灌溉分区、摄像头点位、环境监测点等业务对象，并与场景模型、IoT 设备绑定 | 业务对象配置表 |
| 指标字典 | 统一温度、湿度、光照、pH、EC、水压、流量、CO2、PM2.5 等指标的 key、单位、精度、正常范围 | 指标字典配置 |
| 阈值规则 | 支持按设备、地块、温室、业务类型配置多级阈值和告警等级 | 业务规则配置 |
| 通用接口 | 封装最新值、历史曲线、聚合统计、告警列表、控制指令等 API | 业务数据 API |
| 统一交互 | 点击 3D 对象后展示业务详情，支持从列表定位到 3D 场景对象 | 场景与业务联动 |

#### 5.1 土壤墒情系统

**业务目标**：掌握不同地块、不同土层的土壤水分和温度变化，辅助灌溉决策。

| 任务 | 详细 | 产出 |
|------|------|------|
| 墒情设备接入 | 接入土壤温度、土壤湿度、土壤电导率传感器，支持表层/中层/深层数据 | 墒情数据通道 |
| 地块分区管理 | 将传感器绑定到地块或作物区域，支持按地块查看实时墒情 | 地块墒情视图 |
| 分层数据展示 | 以剖面图、柱状图或分层标签展示不同土层湿度/温度 | 土层分布组件 |
| 墒情热力图 | 将湿度、温度、缺水指数叠加到 3D 地形或地块平面 | 墒情热力图 |
| 异常诊断 | 对干旱、过湿、传感器离线、数据突变进行高亮和告警 | 墒情告警规则 |
| 历史趋势 | 支持 24 小时、7 天、30 天趋势查询和导出 | 墒情趋势图 |

**关键指标**：土壤温度、土壤湿度、土壤 EC、缺水指数、异常地块数量。

#### 5.2 气候/气象监测

**业务目标**：汇聚园区气象站和外部天气数据，为种植、灌溉、通风、预警提供环境依据。

| 任务 | 详细 | 产出 |
|------|------|------|
| 气象站接入 | 接入空气温度、湿度、风速、风向、降雨量、光照、气压等数据 | 气象数据通道 |
| 气象站模型联动 | 在 3D 场景中展示气象站位置、在线状态、实时数据浮窗 | 气象站 3D 点位 |
| 趋势分析 | 展示 24 小时和 7 天气象趋势，支持多指标叠加对比 | 气象趋势面板 |
| 极端天气预警 | 配置高温、低温、大风、暴雨、强光等预警规则 | 气象预警规则 |
| 外部天气对接 | 可选对接第三方天气 API，用于补充未来天气预报 | 天气预报卡片 |
| 场景效果联动 | 根据天气状态切换光照、雨雪、雾效、风向箭头等可视效果 | 天气场景联动 |

**关键指标**：空气温度、空气湿度、风速、风向、降雨量、光照强度、气象预警数量。

#### 5.3 水肥灌溉系统

**业务目标**：可视化灌溉管网、阀门、水泵和施肥设备状态，形成计划、执行、监控、告警的闭环。

| 任务 | 详细 | 产出 |
|------|------|------|
| 管网建模 | 在场景中绘制主管、支管、滴灌带、水泵、蓄水池、阀门等对象 | 灌溉管网 3D 图层 |
| 设备状态监测 | 接入阀门开关、水泵启停、流量、水压、水位、肥液浓度等数据 | 灌溉设备监控 |
| 灌溉计划 | 支持按地块、作物、时间段配置灌溉计划和施肥计划 | 灌溉计划时间轴 |
| 执行过程展示 | 计划执行时高亮灌溉分区，管线展示水流方向和流速 | 灌溉过程动画 |
| 异常告警 | 对低水压、流量异常、阀门故障、水位过低、计划失败等触发告警 | 灌溉告警规则 |
| 远程控制 | 提供阀门开关、水泵启停的控制入口，记录操作日志 | 设备控制面板 |

**关键指标**：阀门状态、水泵状态、水压、瞬时流量、累计用水量、肥液浓度、计划完成率。

#### 5.4 大棚智能控制

**业务目标**：对温室内环境和执行设备进行集中监控，实现温度、湿度、光照、CO2 的精细化调节。

| 任务 | 详细 | 产出 |
|------|------|------|
| 温室内部场景 | 支持从园区场景进入温室内部视角，展示作物、设备、传感器点位 | 温室内部 3D 场景 |
| 环境数据接入 | 接入棚内温度、湿度、光照、CO2、土壤湿度等数据 | 温室环境数据面板 |
| 执行设备联动 | 绑定卷帘、风机、湿帘、天窗、补光灯、加热器、喷淋等设备状态 | 温室设备状态图 |
| 控制策略展示 | 展示目标温度、目标湿度、控制模式、PID 或规则控制过程 | 控制策略可视化 |
| 自动/手动控制 | 支持自动控制模式、手动控制模式切换，并记录操作日志 | 温室控制面板 |
| 作物生长辅助 | 按作物阶段配置适宜环境范围，偏离时提示调控建议 | 作物环境建议 |

**关键指标**：棚内温度、棚内湿度、光照、CO2、设备运行状态、控制模式、环境达标率。

#### 5.5 视频监控系统

**业务目标**：在 3D 园区中统一管理摄像头点位、实时画面、录像回放和 AI 识别告警。

| 任务 | 详细 | 产出 |
|------|------|------|
| 摄像头点位管理 | 摄像头模型绑定真实设备编号、朝向、覆盖区域、视频地址 | 摄像头点位图层 |
| 实时视频查看 | 点击摄像头弹出实时画面，支持 HLS/WebRTC/RTSP 转码流 | 实时视频窗口 |
| 录像回放 | 支持按摄像头、时间范围查询录像，提供时间轴回放 | 录像回放面板 |
| AI 识别告警 | 对人员入侵、烟火、车辆异常、设备遮挡等事件接入识别结果 | 视频 AI 告警 |
| 告警定位 | 告警发生时自动定位到摄像头点位，并展示截图、视频片段、处置状态 | 视频告警处置 |
| 巡检模式 | 支持摄像头轮巡、重点区域收藏、全屏监控模式 | 视频巡检视图 |

**关键指标**：摄像头在线率、告警数量、未处置事件、录像可用率、重点区域覆盖率。

#### 5.6 环境监测

**业务目标**：监测园区空气、水质、噪声等综合环境指标，支撑生态农业展示和安全运营。

| 任务 | 详细 | 产出 |

| 噪声监测 | 接入园区边界和生产区噪声数据，支持昼夜阈值规则 | 噪声监测面板 |
| 综合评分 | 按空气、水质、噪声、气象、土壤等维度计算环境综合评分 | 环境评分模型 |
| 雷达图展示 | 使用雷达图展示各环境维度评分，支持点击下钻到原始指标 | 环境雷达图 |

**关键指标**：PM2.5、PM10、CO2、pH、溶解氧、浊度、噪声、环境综合评分。

## 五、数据库扩展设计

```sql
-- 扩展现有 model 表，增加分类字段
ALTER TABLE model ADD COLUMN category VARCHAR(32) DEFAULT '';
ALTER TABLE model ADD COLUMN tags VARCHAR(256) DEFAULT '';
ALTER TABLE model ADD COLUMN thumbnail VARCHAR(256) DEFAULT '';
ALTER TABLE model ADD COLUMN metadata JSON;

-- IoT 设备表
CREATE TABLE iot_device (
  deviceId VARCHAR(64) PRIMARY KEY,
  deviceName VARCHAR(128),
  deviceType VARCHAR(32),   -- sensor, camera, controller, weather_station
  modelId INT,              -- 关联的 3D 模型
  position JSON,            -- 场景中位置
  mqttTopic VARCHAR(256),
  status VARCHAR(16) DEFAULT 'offline',
  lastDataTime DATETIME,
  config JSON,
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- IoT 数据时序表
CREATE TABLE iot_data (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  deviceId VARCHAR(64),
  metricKey VARCHAR(64),    -- temperature, humidity, soil_moisture, etc.
  metricValue DOUBLE,
  unit VARCHAR(16),
  timestamp DATETIME,
  INDEX idx_device_time (deviceId, timestamp)
);

-- 告警记录表
CREATE TABLE alert_log (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  deviceId VARCHAR(64),
  alertType VARCHAR(32),    -- threshold, offline, anomaly
  severity VARCHAR(16),     -- info, warning, critical
  message TEXT,
  acknowledged BOOLEAN DEFAULT FALSE,
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 场景模板表
CREATE TABLE scene_template (
  templateId VARCHAR(64) PRIMARY KEY,
  templateName VARCHAR(128),
  category VARCHAR(32),     -- greenhouse, farmland, park
  thumbnail VARCHAR(256),
  sceneData JSON,           -- 完整场景配置
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 九、风险与建议

1. **模型质量参差不齐**：CC0 模型需要人工筛选，建议先下载 100+ 个再精选
2. **性能问题**：大量 3D 模型 + 数据实时刷新需要 LOD 和实例化优化
3. **IoT 数据来源**：开发阶段用模拟数据，生产环境需对接真实 MQTT Broker
4. **TRELLIS.2 生成质量**：单图生成对复杂农业设备效果有限，高质量模型仍需手工建模
