# 第 1 周：不接 Eino，先做规则版 MVP

## 1. 本周目标

先把“自然语言 -> 场景方案 -> 网页自动摆放模型”这条主链路跑通，不依赖 Eino、不依赖 LLM、不依赖 TRELLIS.2。
这一周的重点不是“聪明”，而是“先能用”。

## 2. 本周范围

- 先支持 10 到 20 类农业常用资产，例如温室、农田、气象站、摄像头、水塔、灌溉设备、仓库、管理楼、道路。
- 先支持 5 类基础布局：单个、行列、网格、左右分区、沿道路。
- 先用关键词 + 模板 + 规则引擎生成 `ScenePlan`。
- 先不做 LLM，不做 Eino，不做 TRELLIS.2，不做正式资产生成。
- 先不允许自动写正式场景库，只做预览和草稿逻辑。

## 3. 具体任务

### 3.1 定义中间协议

新增统一数据结构：

- `ScenePlan`
- `BuildModel`
- `SceneBuildResponse`
- `AssetSemantic`

这一步的目标是把“语义”与“Three.js 真实参数”分开。

### 3.2 建立模型语义 mock 数据

先在后端或前端放一份 mock 资产表，包含：

- `assetKey`
- 中文名
- 别名
- 分类
- 默认缩放
- 占地尺寸
- 布局规则

例如：

- `greenhouse` -> 温室大棚
- `weather_station` -> 气象站
- `corn` -> 玉米

### 3.3 实现规则布局器

实现一个纯规则的 `layout.solve`：

- `left / right / center`
- `north / south / east / west`
- `row / column / grid`
- `along_path`

输出要直接变成当前平台可用的：

```json
{
  "url": "/models/greenhouse.glb",
  "options": {
    "offset": { "x": 300, "y": 0, "z": -200 },
    "scale": 1,
    "angle": 0
  }
}
```

### 3.4 接入 `/semantic/build/plan`

先做一个规则版接口：

- 输入：`message`、`sceneName`、`mode`
- 输出：`scenePlan`、`models[]`、`warnings[]`、`missingAssets[]`

内部逻辑可以是：

1. 关键词识别
2. 模板匹配
3. 规则布局
4. 输出结果

### 3.5 前端新增“AI 搭建”面板

在现有场景编辑页加一个面板，支持：

- 输入自然语言
- 点击生成方案
- 查看对象清单
- 查看缺失资产
- 点击“应用到场景”

应用时直接复用现有 `scene.loadModel(url, options)`。

### 3.6 准备测试样例

先准备 5 条可演示需求：

- 智慧农业示范园区
- 标准温室场景
- 农田 + 气象站组合
- 现有场景补设备
- 综合园区模板

## 4. 产出物

- `ScenePlan` 数据结构
- 规则布局器
- `/semantic/build/plan` 规则版接口
- 前端 AI 搭建面板
- 5 条测试样例

## 5. 验收标准

- 输入标准农业描述后，可以在网页里自动放置模型。
- 自动生成的模型能正常拖拽、缩放、旋转。
- 保存后重新打开场景不丢失。
- 没有模型时不会崩溃，而是给出缺失提示。

## 6. 风险与处理

- 风险：规则太死，表达稍微变化就识别不到。  
  处理：先做小词表，优先覆盖高频农业词汇。

- 风险：布局重叠。  
  处理：布局器里预留最小间距和碰撞修正。

- 风险：模板太少。  
  处理：先做 3 到 5 个高频模板，后续继续补。
