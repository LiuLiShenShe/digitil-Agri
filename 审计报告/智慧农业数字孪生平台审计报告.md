# 智慧农业数字孪生平台审计报告

审计时间：2026-05-11 15:54 CST

- 运行日志：`/data/fj/数字孪生/logs/frontend.log`、`/data/fj/数字孪生/logs/backend.log`

## 1. 总体结论

按严格项目验收口径判定：**当前系统是“可演示的智慧农业数字孪生原型”，不是“建设方案描述的完整智慧农业数字孪生平台”。**

当前已经具备 3D 场景编辑、模型库、IoT 模拟数据、设备数据接口、告警接口、监控中心大屏、业务子系统总览等基础能力，可以支撑演示、联调和下一阶段建设。但建设方案中 Phase 5 的 6 个业务子系统、视频监控闭环、真实 MQTT 接入、业务对象建模、权限与操作日志、报表、控制指令闭环等关键交付项仍未达到验收标准。

本次审计给出的交付判定：

| 维度 | 判定 | 说明 |
| --- | --- | --- |
| 演示可用性 | 有条件通过 | 能打开页面、显示 3D 场景、模型、IoT 模拟数据和监控看板 |
| 方案完成度 | 不通过 | Phase 5/6 多项核心验收项未完成，只能称为部分实现 |
| 生产可用性 | 不通过 | 缺权限、安全、真实设备接入、视频流服务、控制闭环、测试和运维保障 |
| 数据真实性 | 高风险 | 多处依赖模拟器、静态配置或前端本地模拟，不能等同真实业务系统 |
| 后续建议 | 先收敛范围再验收 | 需要明确“演示版”和“生产版”的边界，避免页面存在被误认为能力完成 |

粗略进度评估：

- 演示原型完成度：约 55% - 60%
- 建设方案功能完成度：约 35% - 45%
- 生产上线准备度：约 20% - 30%

## 3. 当前已经具备的功能

### 3.1 3D 场景编辑器

当前前端首页 `/` 是实际可用的场景编辑工作台，包含：

- 3D 场景容器：`SceneContainer.vue`
- 顶部菜单：`HeadMenu.vue`
- 属性面板：`ProperityPane.vue`
- 场景设置：`SceneSetting.vue`
- 图层面板：`LayerPanel.vue`
- 地形工具栏：`TerrainToolbar.vue`
- 数据可视化面板：`DataVizPanel.vue`
- IoT 设备面板：`IoTDevicePanel.vue`
- 告警面板：`AlertPanel.vue`
- 摄像头视图：`CameraView.vue`
- 保存弹窗：`SaveDialog.vue`
- 模型树弹窗：`ModelTreeDialg.vue`

已实现能力：

- 场景保存、加载、默认场景接口
- 模型树加载
- 模型拖入或选择后进入场景
- 基础属性编辑
- 图层创建、重命名、显隐管理
- 地形/地表相关工具
- 场景模板入口
- IoT 设备绑定入口
- 告警查看入口

判定：**部分完成，能支撑演示；离成熟编辑器仍有差距。**

主要问题：

- 缺模型加载失败的完整兜底和资产一致性校验。
- 模板中引用的部分模型路径与当前资产目录不完全一致，存在模板点击后模型丢失风险。
- 缺少批量选择、撤销/重做、对象锁定、复制粘贴、吸附规则、快捷键体系等成熟编辑器能力的完整验收。
- 复杂场景性能未压测，主包过大。

### 3.2 模型资产库

后端已提供：

- `/sceneApi/model/list`
- `/sceneApi/admin/import-models`
- `/sceneApi/admin/stats`
- `/scene-assets/models/*` 静态模型访问

当前模型数量已超过方案 Phase 1 “80+”的最低数量目标，后端统计为 388 个节点、342 个叶子模型。

判定：**数量达标，质量和管理能力未达标。**

主要问题：

- 缩略图只有 7 个，模型库展示质量明显不足。
- 缺少完整尺寸、标签、来源、版权、适用场景、LOD、面数、贴图大小等元数据。
- 缺少模型质量验收机制，例如加载耗时、面数上限、贴图压缩、命名规范。
- 前端 public 模型与后端资产库存在两套目录，容易产生路径不一致和重复维护。

### 3.3 数据可视化组件

- 雷达图
- 3D 柱状图
- 热力图
- 饼图

### 3.6 业务中心

前端路由 `/business` 已存在，后端 `/sceneApi/business/overview` 可返回 6 个业务子系统的状态、指标、工作流和缺口。

覆盖的 6 个子系统：

- 土壤墒情系统
- 气象监测系统
- 水肥灌溉系统
- 大棚智能控制
- 视频监控系统
- 综合环境监测

判定：**这是“业务验收总览页”，不是 6 个业务子系统本体。**

优点：

- 页面明确展示 partial、blocked、missing 等状态，避免假装已完成。
- 后端数据来自 IoT 最新值、告警和部分真实接口，不是纯静态页面。
- 可以作为后续验收驾驶舱使用。

问题：

- 没有独立的 6 个子系统页面。
- 没有业务对象配置表和管理界面。
- 没有计划、控制、处置、录像、报表等业务闭环。
- 没有权限、操作日志、审批、工单。
- 当前 completionRate 57.17 只是审计/估算指标，不能作为生产验收指标。

## 6. 当前缺失的关键功能

### 6.1 平台底座缺失

- 用户登录、认证、RBAC 权限。
- 租户/园区/项目隔离。
- 操作日志、审计日志。
- 后台配置中心。
- 健康检查、版本信息、运行状态接口。
- 数据库迁移管理。
- CI/CD、自动化测试和发布流程。

### 6.2 业务对象建模缺失

建设方案要求地块、温室、灌溉分区、摄像头点位、环境监测点等业务对象与 3D 模型、IoT 设备绑定。当前只看到模型和设备绑定的基础接口，没有形成完整业务对象体系。

缺失项：

- 地块管理
- 温室管理
- 灌溉分区管理
- 摄像头点位管理
- 环境监测点管理
- 作物/品种/生长阶段管理
- 业务对象与模型、设备、指标的统一绑定关系

### 6.3 控制闭环缺失

当前系统可以看数据，但不能证明可以安全地控制设备。

缺失项：

- 控制指令 API
- 指令审批
- 指令下发状态机
- 成功/失败回执
- 手动/自动模式切换
- 设备互锁和安全保护
- 操作审计

### 6.4 视频能力缺失

当前视频相关能力主要停留在前端组件和摄像头模拟设备。

缺失项：

- RTSP 拉流
- HLS/WebRTC 转码服务
- 实时视频播放后端
- 录像回放
- 截图和片段存储
- AI 识别事件接入
- 视频告警处置
- 摄像头轮巡和全屏监控

### 6.5 数据治理与报表缺失

缺失项：

- 指标字典
- 阈值规则配置界面
- 数据质量标记
- 异常值处理
- 聚合统计
- 24h/7d/30d 趋势查询
- CSV/Excel/PDF 导出
- 环境日报自动生成
- 数据归档和清理策略

## 7. 主要风险

### 风险 1：页面存在被误认为功能完成

系统现在有不少页面、菜单和卡片，但很多只是状态展示或模拟数据。若按页面数量汇报，会高估项目完成度。

建议：所有演示页面必须标注数据来源和完成级别，验收材料中区分“真实接入”“模拟接入”“静态展示”“未实现”。

### 风险 2：安全能力不足

当前未发现完整登录、权限和审计闭环；CORS 允许范围也需要收敛。Swagger、管理接口、模型导入接口如果在生产环境暴露，会带来安全风险。

建议：生产前必须补认证、权限、接口鉴权、操作审计、CORS 白名单和 Swagger 暴露策略。

### 风险 3：真实设备接入未打穿

IoT 模拟器可以跑通演示，但不能替代真实设备接入验收。MQTT adapter 存在不代表真实链路完成。

建议：至少接入 1 台真实气象站、1 组土壤传感器、1 个灌溉控制器，完成端到端验收。

### 风险 4：告警数据失控

审计时未确认告警已达到 91 条，且历史告警仍在累积。没有批量确认、归档、抑制和清理机制，后续会影响展示可信度。

建议：增加告警生命周期管理，包括批量确认、关闭、归档、抑制、升级、统计和清理。

### 风险 5：前端性能风险

构建产物约 63M，主 JS 包约 3.4M，且 Vite 提示 chunk size warning。模型资产规模增加后，首屏和场景加载性能风险会上升。

建议：拆包、懒加载、模型压缩、LOD、实例化渲染、贴图压缩和资源预加载策略必须纳入验收。

### 风险 6：日志与运维能力不足

日志中存在重复输出和历史错误痕迹；缺少健康检查、指标监控、告警通知和版本信息。

建议：统一日志格式、减少重复输出、增加 `/healthz`、`/readyz`、版本接口和基础 Prometheus 指标。

## 8. 整改优先级

### P0：必须先做，否则不能继续宣称平台完成

1. 明确演示版边界，在页面和报告中标出模拟数据、真实数据、未完成能力。
2. 补用户认证、权限、接口鉴权、操作日志。
3. 建立业务对象模型：地块、温室、灌溉区、摄像头、监测点。
4. 把 6 个业务子系统从“总览卡片”拆成真实页面和接口。
5. 接入至少一条真实 MQTT 设备链路，并形成验收记录。
6. 增加告警批量确认、归档、抑制、清理。
7. 补模型元数据和缩略图生成流程。
8. 增加健康检查和部署检查脚本。

### P1：完成后才接近方案验收

1. 水肥灌溉计划、执行状态和控制指令闭环。
2. 大棚控制策略、执行设备、回执和安全互锁。
3. 视频流后端：RTSP/HLS/WebRTC 至少选择一种打通。
4. 历史趋势、聚合统计、导出和日报。
5. 3D 场景告警定位与业务对象联动。
6. 阈值规则配置界面和指标字典。
7. 前端拆包、模型懒加载和性能压测。

### P2：提升生产质量

1. 自动化单元测试、接口测试和 E2E 测试。
2. CI/CD 和数据库迁移。
3. 设备资产台账、维护记录和校准记录。
4. 多园区、多租户和角色隔离。
5. 统一报表中心。
6. 运行监控、错误追踪和容量规划。

## 9. 建议验收清单

下次验收不建议只看页面，应按下面清单逐项验证：

| 验收项 | 通过标准 |
| --- | --- |
| 真实设备接入 | 至少 3 类真实设备端到端写入、展示、告警 |
| 业务对象绑定 | 地块/温室/灌溉区/摄像头/监测点可配置并绑定模型和设备 |
| 6 个业务子系统 | 每个系统有独立页面、接口、历史趋势、告警和处置入口 |
| 控制闭环 | 至少 1 类执行设备支持指令下发、回执、失败处置和日志 |
| 视频监控 | 至少 1 路真实视频流可播放，支持点位打开 |
| 告警系统 | 规则可配置，告警可确认、关闭、归档、定位 |
| 报表 | 环境日报可生成并导出 |
| 权限 | 不同角色访问范围不同，关键操作有审计记录 |
| 性能 | 大场景加载、模型拖拽和监控大屏刷新有明确指标 |
| 安全 | 管理接口、Swagger、CORS、静态资源访问策略符合部署要求 |

## 10. 最终判定

当前项目已经从原始编辑器向智慧农业方向推进了一步，且具备可演示基础。但从建设方案角度看，核心业务闭环仍没有完成，特别是 Phase 5 的 6 个业务子系统和 Phase 6 的完整监控运营能力。

严格结论：

**不能按“智慧农业数字孪生平台建设完成”验收。可以按“智慧农业数字孪生演示原型完成，进入业务系统补齐和真实设备联调阶段”验收。**

建议项目汇报口径调整为：

> 当前已完成数字孪生编辑器农业化改造、模型库扩充、IoT 模拟数据链路、监控中心雏形和业务验收总览。下一阶段重点补齐真实设备接入、6 个业务子系统、视频流、控制闭环、权限审计和报表能力。
