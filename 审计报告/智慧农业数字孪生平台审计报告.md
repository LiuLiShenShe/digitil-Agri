# 智慧农业数字孪生平台功能汇报与审计报告

审计日期：2026-05-20  
审计对象：

- 建设方案：`/data/fj/数字孪生/智慧农业数字孪生平台建设方案.md`
- 前端工程：`/data/fj/数字孪生/digital-twingo/scene-design-v2`
- 后端工程：`/data/fj/数字孪生/digital-twingo/scene-server-go`
- 资产目录：`/data/fj/数字孪生/digital-twingo/scene-server-go/scene-assets`
- 审计方式：源码审阅、配置审阅、资产目录扫描、构建与测试命令验证

## 1. 汇报摘要

当前系统已经形成“智慧农业数字孪生演示平台”的主体形态，具备 3D 场景搭建、农业模型资产库、IoT 设备与模拟数据、告警、监控中心大屏、业务子系统验收视图、AI 只读助手、基于 Eino DeepAgents 的场景搭建智能体、模型语义检索、自然语言语义理解、自动位置放置、缺失资产补齐任务等功能入口。

从功能展示角度看，系统已经不是单一 3D 编辑器，而是扩展成以下 5 个页面能力：

| 页面 | 路由 | 当前作用 |
| --- | --- | --- |
| 场景编辑工作台 | `/` | 3D 场景编辑、模型布置、图层、地形、IoT、告警、摄像头、Eino Agent 语义搭建 |
| 监控中心大屏 | `/monitor` | 园区指标、设备状态、告警、能耗、产量、环境日报式展示 |
| 业务中心 | `/business` | 6 个农业业务子系统的完成度、指标、工作流和缺口汇总 |
| AI 助手 | `/assistant` | 只读读取模型、场景、IoT、告警、监控、业务数据，辅助审计和运维分析 |
| 关于页 | `/about` | 平台说明入口 |

严格审计结论：**当前系统可以按“智慧农业数字孪生演示原型/联调原型”汇报，不宜按“完整生产级智慧农业数字孪生平台”验收。**

核心原因是：真实设备接入、6 个独立业务子系统、视频流闭环、控制指令闭环、权限审计、报表导出、数据治理和生产运维能力仍未补齐。另一方面，Eino 智能体、语义搭建、模型语义检索和自动布局放置属于当前系统的实质亮点，应作为“智能化搭建能力”单独汇报。

## 2. 当前系统功能全景

### 2.1 3D 场景编辑与农业化搭建

系统首页是 3D 场景编辑工作台，前端由 `MainView.vue` 组合以下核心组件：

- `SceneContainer.vue`：Three.js 场景容器，承载模型、地面、相机、灯光、交互。
- `HeadMenu.vue`：顶部菜单，提供保存、加载、页面跳转等操作入口。
- `ProperityPane.vue`：模型属性面板，支持位置、旋转、缩放等对象属性编辑。
- `SceneSetting.vue`：场景设置。
- `LayerPanel.vue`：图层管理。
- `TerrainToolbar.vue`：地形和地表编辑工具。
- `DataVizPanel.vue`：数据可视化面板。
- `IoTDevicePanel.vue`：IoT 设备面板。
- `AlertPanel.vue`：告警面板。
- `CameraView.vue`：摄像头查看入口。
- `SemanticBuilderPanel.vue`：自然语言语义搭建入口。
- `SaveDialog.vue`、`ModelTreeDialg.vue`：保存与模型树弹窗。

后端提供场景接口：

| 能力 | 接口 |
| --- | --- |
| 保存场景 | `POST /sceneApi/scene/saveScene` |
| 场景列表 | `GET /sceneApi/scene/sceneList` |
| 加载场景 | `GET /sceneApi/scene/loadScene` |
| 默认场景 | `GET /sceneApi/scene/defaultScene` |

功能判定：**可演示，部分成熟。**

已经具备场景搭建、模型选择/布置、基础属性编辑、图层、地形工具、保存加载等基础能力。与建设方案中的成熟拖拽式编辑器相比，仍缺少完整的批量操作、撤销重做、对象锁定、吸附对齐、复制粘贴、复杂场景性能验收和资产路径一致性校验。

系统已建立农业模型资产体系，覆盖建筑、温室、灌溉、机械、植物、IoT、地形、装饰等类型。

本次目录扫描结果：

| 项目 | 数量 |
| --- | ---: |
| 后端 `scene-assets` 下 `.glb` 文件 | 593 |
| 后端 `scene-assets` 下图片文件 | 17 |
| 前端 `public/models` 下 `.glb` 文件 | 27 |

功能判定：**数量已明显超过 Phase 1 最低目标，质量治理不足。**

主要问题：

- 模型数量与可用质量不能等价，仍需补尺寸、面数、贴图、来源、版权、标签、业务适用场景等元数据。
- 缩略图数量明显少于模型数量，模型库浏览体验和验收材料支撑不足。
- 前端 `public/models` 与后端 `scene-assets/models` 并存，存在双资产源和路径不一致风险。
- 批量导入逻辑主要按目录名映射分类，缺少质量检测、重名处理、版权校验和导入回滚。

### 2.8 Eino 智能体与自然语言语义搭建

系统已加入 `SemanticBuilderPanel.vue` 和后端 `SceneBuilderAgent`。用户可以输入类似“搭一个智慧农业示范园区，左侧六块玉米地，右侧三个温室，中间一条道路”的自然语言，由后端智能体完成语义理解、模型检索、场景规划、布局求解、结果校验，再由前端把模型自动放置到 Three.js 场景中。

后端接口：

| 能力 | 接口 |
| --- | --- |
| 生成语义搭建计划 | `POST /sceneApi/semantic/build/plan` |
| 语义资产目录 | `GET /sceneApi/semantic/assets` |
| 示例提示词 | `GET /sceneApi/semantic/samples` |

当前智能体链路：

```text
用户自然语言
  -> 前端采集当前场景上下文、已选对象、已有对象
  -> /semantic/build/plan
  -> SceneBuilderAgent
  -> Eino DeepAgents 调度或确定性工具流水线
  -> scene.current 读取当前场景上下文
  -> model.search 做模型语义检索
  -> model.metadata 读取资产语义元数据
  -> scene.plan 生成对象组级 ScenePlan
  -> layout.solve 求解具体模型位置
  -> layout.validate 校验布局和缺失资产
  -> 返回 models 加载队列、missingAssets、agentTrace
  -> 前端自动 loadModel 放置模型
```

能力特点：

- 后端已引入 `github.com/cloudwego/eino v0.5.14`。
- `SceneBuilderAgent` 使用 Eino DeepAgents 作为智能体框架，配置了 `deep.New`、ADK、工具节点和最大迭代轮数。
- 已封装 OpenAI-compatible ChatModel：`EinoOpenAIChatModel.go`，可对接兼容 OpenAI Chat Completions 的模型服务。
- 智能体只开放白名单工具，包含 `model.search`、`model.metadata`、`scene.current`、`scene.plan`、`layout.solve`、`layout.validate`。
- 智能体不允许 Shell、文件系统、任意 HTTP 或数据库写入，属于受控场景搭建智能体。
- 配置 LLM 后优先尝试 Eino DeepAgents 调度；未配置或调用失败时自动回退到确定性工具流水线。
- 返回 `agentTrace`，前端能展示 Agent 模式、耗时、工具调用序列和每个工具状态。
- 支持 append/preview 模式：前端根据“继续、补齐、现有、当前”等语义判断是在当前场景追加还是清空后预览。
- 支持读取当前场景上下文，包括场景名、已有对象、选中对象、已选对象，用于“在当前场景补几个摄像头”这类增量搭建。

功能判定：**Eino 智能体与语义化自动搭建能力有实质实现，是当前系统最重要的智能化亮点。**

但需要注意：当前配置中 `llm.enabled: false`，因此默认运行时更稳定依赖“白名单工具流水线 + 规则规划器”。Eino DeepAgents 的 LLM 调度能力已经接入代码，但需要配置可用模型服务后才能按 DeepAgents 模式完整验收。

### 2.9 模型语义检索、语义理解与位置放置

系统已经实现面向农业场景的轻量语义资产目录和语义检索，不是单纯按文件名加载模型。

语义资产目录包含：

| assetKey | 语义名称 | 别名示例 | 默认布局/区域 |
| --- | --- | --- | --- |
| `greenhouse` | 温室大棚 | 温室、大棚、玻璃温室、暖棚 | 东侧/西侧，行、列、网格 |
| `corn` | 玉米地 | 玉米、玉米田、农田 | 西侧/东侧，网格/行 |
| `wheat` | 小麦田 | 小麦、麦田 | 西侧/东侧，网格/行 |
| `rice` | 水稻田 | 水稻、稻田、水田 | 西侧/东侧，网格/行 |
| `weather_station` | 气象站 | 气象站、环境监测站、监测站 | 中心，单点 |
| `irrigation` | 灌溉设备 | 灌溉、水泵、喷灌、滴灌 | 中心/沿道路 |
| `water_tower` | 水塔 | 水塔、蓄水塔、供水塔 | 北侧/南侧 |
| `warehouse` | 仓库 | 仓库、农资仓库、库房 | 北侧/南侧 |
| `road` | 道路 | 道路、主路、贯穿 | 中心/沿道路 |
| `camera` | 摄像头 | 摄像头、监控、监控杆 | 沿道路/行 |

语义理解能力包括：

- 同义词识别：例如“玻璃房、暖棚、大棚”可归一到 `greenhouse`。
- 数量解析：支持“一二三四五六七八九十”和数字，能识别“三个温室”“六块玉米地”。
- 方位解析：支持左侧/右侧/东侧/西侧/北侧/南侧/中间/入口等表达。
- 布局解析：支持网格、矩阵、纵向、横向、沿路、贯穿等布局词。
- 模板推断：识别“综合园区、农业园区、示范园区、标准温室、补设备”等意图。
- 关系推断：可生成气象站靠近中心、灌溉服务作物/温室、道路贯穿中心等 `relations`。

位置放置能力包括：

- 将对象组级 `ScenePlan` 转成具体 `BuildModel` 加载队列。
- 支持 `single`、`row`、`column`、`grid`、`along_path` 五类布局。
- 按 `west/east/north/south/center/northwest/...` 计算区域中心。
- 按模型 footprint 计算间距。
- 使用 `avoidCollision` 做基础碰撞规避。
- 使用 `clampPoints` 把模型限制在地面范围内。
- 按对象类型设置角度，例如温室横排旋转、南北建筑朝向、沿道路对象交错朝向。
- 前端 `applyPlan` 会设置地面、网格、灯光，并逐个调用 `scene.loadModel` 自动放置模型。

缺失资产闭环：

- 如果语义资产存在但没有 GLB，例如 `camera`、`sensor`、`tractor`、`drone`，系统不会直接失败。
- `layout.solve` 会先放置占位模型，并在 `missingAssets` 中记录 `fallbackModelKey` 和 `placementRefs`。
- 前端展示缺失资产、参考图状态、生成任务状态、进度和替换占位模型入口。
- 后端可通过 `/asset/jobs` 创建 TRELLIS.2 图片转 GLB 任务，并把生成结果与缺失资产关联。

功能判定：**模型语义检索、语义理解、自动布局放置和缺失资产占位闭环已经形成完整 MVP。**

需要注意：这里的“语义检索”是模型资产级语义检索/别名匹配/白名单检索，不是文档知识库 RAG 的向量检索。文档 RAG 目前仍是预留状态。

| 创建生成任务 | `POST /sceneApi/asset/jobs` |
| 查询任务 | `GET /sceneApi/asset/jobs/:id` |
| 任务列表 | `GET /sceneApi/asset/jobs` |
| 审核通过 | `POST /sceneApi/asset/jobs/:id/approve` |
| 驳回任务 | `POST /sceneApi/asset/jobs/:id/reject` |

实现方式是 Go 后端将图片和参数转发给外部 Python 服务 `http://127.0.0.1:9020/generate`，再轮询 `/status/:jobId` 获取生成结果。

功能判定：**工作流接口已具备，能力依赖外部 Python/TRELLIS 服务。**

这项能力不能按“后端自包含生成”验收。实际交付时需要同时验收 Python 服务部署、GPU/模型依赖、任务队列、失败重试、资源清理、生成资产质量和审核入库流程。

## 7. 主要风险

### 7.1 演示能力被误认为生产能力

系统页面丰富，容易让非技术评审误以为 6 个业务系统已经完成。实际当前很多能力仍是总览、模拟、占位或半闭环。

建议：汇报材料中统一标注“真实接入”“模拟接入”“页面展示”“待实现”四类状态。

### 7.2 真实设备接入风险

当前 IoT 模拟器开启，系统可持续产生数据和告警。但模拟器不能替代真实 MQTT 设备验收。

建议：至少完成气象站、土壤传感器、灌溉控制器三类真实设备端到端联调，并形成联调记录。

### 7.3 控制闭环与安全风险

农业设备控制涉及阀门、水泵、风机、补光、卷帘等执行设备。当前缺少指令审批、下发状态机、失败回执、操作审计和安全互锁。

建议：在控制功能上线前，先补权限、审计、指令日志、回执和手动/自动模式边界。

### 7.4 视频能力风险

当前视频相关能力主要是页面入口和设备状态，没有完整视频流服务。真实项目验收通常会要求实时流、录像、截图、轮巡和告警联动。

建议：尽快选择 HLS 或 WebRTC 路线，打通至少 1 路真实摄像头。

### 7.5 前端性能风险

本次 `npm run build` 通过，但主 JS chunk 约 3.57MB，Vite 提示 chunk 超过 500KB。随着模型、图表和 Three.js 功能继续增加，首屏加载和低配终端体验会承压。

建议：做路由级拆包、Three.js/ECharts 懒加载、模型压缩、LOD、贴图压缩和大场景压测。

### 7.6 安全与运维风险

当前后端 Swagger 启用，CORS 允许任意 Origin，未发现完整认证授权链路。生产部署如果保持该状态，管理接口、模型导入、资产任务和数据接口都有暴露风险。

建议：生产前补登录认证、RBAC、接口鉴权、CORS 白名单、Swagger 暴露策略、健康检查、版本接口和运行监控。

### 7.7 智能体配置与效果验收风险

Eino DeepAgents 代码链路已经接入，但当前配置中 LLM 默认关闭。若汇报为“DeepAgents 已完整在线运行”，需要补充实际模型服务配置、调用日志、工具调度 trace、失败回退记录和典型提示词验收结果。

建议：把“已接入 Eino 智能体框架”和“已完成 DeepAgents 在线推理验收”分开表述。当前可以确定汇报前者；后者需要在启用 `llm.enabled` 后补验收材料。

### 7.8 语义检索边界风险

当前模型语义检索是基于资产语义目录、别名和规则匹配的白名单检索，适合农业场景模型选择。文档级 RAG 知识库、向量检索、审计报告问答和建设方案检索尚未真正实现。

建议：汇报时使用“模型资产语义检索/语义匹配”，不要笼统称为“RAG 已完成”。
