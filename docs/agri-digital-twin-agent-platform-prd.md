# 智慧农业数字孪生智能体平台 PRD

日期：2026-05-21  
状态：评审草案

## 1. 背景与输入资料

本 PRD 基于以下参考资料整理：

- `openspec/reference/references/01-digital-twin-definition-and-architecture.md`
- `openspec/reference/references/02-smart-agriculture-digital-twin-literature.md`
- `openspec/reference/references/03-agricultural-object-data-models-and-interoperability.md`
- `openspec/reference/references/04-agent-platform-and-orchestration.md`
- `openspec/reference/references/05-3d-glb-asset-pipeline-and-plant-reconstruction.md`
- `openspec/reference/references/06-design-notes-for-this-project.md`
- 现有建设方案与审计材料：当前系统已具备 Vue/Three.js 场景编辑器、Go 后端、农业 GLB 资产库、IoT 模拟链路、告警、监控大屏、业务中心、AI 助手、Eino SceneBuilderAgent、模型语义检索、自动布局和 TRELLIS.2 资产任务入口。

核心判断：当前平台已经具备“智慧农业数字孪生演示原型”的主体骨架。下一阶段不应继续只堆叠页面和模型数量，而应补齐数字孪生成立所需的对象模型、数据绑定、状态同步、资产治理和 Agent 可追溯运维闭环。

## 2. 头脑风暴收敛

### 2.1 可选方向

| 方向 | 说明 | 优点 | 风险 |
| --- | --- | --- | --- |
| A. 继续扩 3D 资产和页面 | 重点扩 GLB 数量、业务页面和大屏效果 | 演示可见度高，短期汇报直观 | 容易停留在静态可视化，数字孪生内核不足 |
| B. 先补孪生底座 | 建农业业务对象、3D 绑定、指标、时序、事件、状态和对象查询 | 能让平台从“3D 场景”升级为“可查询、可同步、可诊断的孪生系统” | 短期视觉变化不如新增页面明显 |
| C. 优先做多 Agent 运维 | 扩展 Agent 工具、trace、日报、告警解释、资产审计 | 凸显智能体平台特色，论文/汇报亮点强 | 没有对象和数据底座时，Agent 只能做表层分析 |
| D. 优先做多保真资产生成 | 打通 F2DMAS/TRELLIS.2/程序化生成和资产元数据治理 | 能形成“多保真农业 GLB 资产池”创新点 | 若缺业务绑定，资产仍只是模型库 |

推荐路线：以 B 为主线，C 和 D 并行小步推进。先让每个 3D 对象能对应农业业务对象、状态、指标、事件和资产版本；再让 Agent 基于这些结构化对象进行搭建、校验、分析、告警解释和报告生成。

### 2.2 产品定位

平台定位为：

> 面向智慧农业数字孪生的多 Agent 场景构建与数据驱动资产更新平台。

平台不是单纯的 3D 编辑器，也不是只会聊天的 AI 助手。它应围绕农业实体建立可同步的虚拟表示，并通过多 Agent 工具链完成场景构建、资产调度、数据绑定、状态同步、异常诊断和报告生成。

### 2.3 核心产品原则

1. 状态同步优先于几何重建：环境、设备、告警、事件和分析状态应实时或日级同步；植株几何按生育期或关键采样点阶段性更新。
2. 不同对象使用不同频率和保真度：传感器实时，日报日级，关键植株阶段级，普通装饰资产静态。
3. 每个可观测对象都必须可查询：3D 对象不只是 mesh，还应能映射到业务对象、状态、指标、关系和历史。
4. Agent 必须可追溯和受控：所有写操作通过白名单工具、显式参数、用户确认、trace、失败原因和回退路径执行。
5. 多保真资产池服务业务目的：F2DMAS 用于关键真实植株，TRELLIS.2 用于普通缺失资产，程序化生成用于规则几何，已有资产优先复用。

## 3. 目标与非目标

### 3.1 产品目标

P0：让“农业数字孪生”成立。

- 建立 Farm、Greenhouse、Parcel、CropRow、Plant、Sensor、Device、Camera 等农业业务对象。
- 支持 3D 场景对象与业务对象绑定。
- 支持业务对象绑定指标、设备、时序数据、事件、分析结果和资产版本。
- 支持从 3D 点选对象查看业务详情，也支持从业务对象定位到 3D 场景。
- 明确每类对象的状态同步频率和几何更新策略。

P1：让“智能体平台”成立。

- 将现有 SceneBuilderAgent 从场景搭建扩展到场景校验、数据绑定、资产审计、告警诊断和日报生成。
- 建立 FarmTwinOrchestrator 总控 Agent 和专用 Agent 分工。
- 扩展工具白名单和 Agent trace 结构。
- 支持确定性回退，避免 LLM 不可用时核心流程失效。

P2：让“多保真资产”成立。

- 统一前端 `public/models` 和后端 `scene-assets` 的资产来源。
- 为 GLB 资产补充来源、许可、缩略图、面数、贴图、体积、LOD、保真度和适用对象。
- 建立资产保真度调度策略：已有资产、F2DMAS、TRELLIS.2、程序化生成、占位模型。
- 支持关键植株的阶段性几何版本和表型数据绑定。

### 3.2 本阶段非目标

- 不承诺完整生产级 6 个业务子系统一次性全部完成。
- 不承诺任意场景的完全自动搭建，先聚焦温室、示范田和综合农业园区。
- 不做每日植株 GLB 重建。
- 不让 Agent 直接控制真实设备。
- 不将 TRELLIS.2 用作关键植株表型测量的可信几何来源。
- 不把模型资产语义检索包装成已完成的文档 RAG 知识库。

## 4. 用户与核心场景

### 4.1 目标用户

| 用户 | 主要诉求 |
| --- | --- |
| 平台演示/售前人员 | 快速搭建可汇报的农业园区、温室和示范田场景 |
| 农业园区运维人员 | 查看设备状态、环境指标、告警、视频点位和日报 |
| 农业技术人员 | 关注作物长势、环境适宜性、灌溉事件和异常解释 |
| 项目实施人员 | 配置业务对象、设备绑定、模型资产和指标规则 |
| 研究/论文作者 | 验证多保真资产、阶段性几何更新和高频状态同步机制 |

### 4.2 关键用户故事

1. 作为实施人员，我希望把一个温室 3D 模型绑定到真实 Greenhouse 对象，以便点选模型时能看到该温室的传感器、作物批次和告警。
2. 作为运维人员，我希望从告警列表定位到 3D 场景中的设备或地块，以便快速判断异常位置和影响范围。
3. 作为演示人员，我希望用自然语言生成番茄温室，并让系统自动补齐模型、布局和缺失资产任务，以便快速构建演示场景。
4. 作为农业技术人员，我希望查看某株关键植株的阶段性 GLB、每日表型数据和长势评分，以便追踪生长变化。
5. 作为平台管理员，我希望看到 Agent 每一步调用了什么工具、输入输出摘要和失败原因，以便审计自动化结果。

## 5. 需求范围

### 5.1 农业对象图谱

必须支持的对象类型：

- Farm：园区/农场。
- Greenhouse：温室。
- Parcel：地块。
- CropRow：作物行。
- Plant：关键单株或代表性植株。
- CropBatch：作物批次。
- Sensor：环境、土壤、水质等传感器。
- Device：阀门、水泵、风机、补光灯、卷帘等执行设备。
- Camera：摄像头点位。
- Operation：灌溉、施肥、巡检、维护等农业事件。
- Observation：环境观测、表型观测、设备状态观测。

每个业务对象至少包含：

- 全局唯一 ID、类型、名称、父级关系。
- 空间位置或所在区域。
- 当前状态、更新时间和数据质量状态。
- 关联的 3D 场景对象。
- 关联的设备、指标、事件和分析结果。

### 5.2 3D 场景对象绑定

需求：

- 每个场景对象可绑定 0 到 1 个主业务对象。
- 一个业务对象可绑定 0 到多个场景对象，用于多视角、多 LOD 或内部/外部场景表达。
- 点选 3D 对象后展示业务详情、实时状态、历史趋势、告警和关联事件。
- 业务对象列表支持“定位到场景对象”。
- 未绑定对象需要在校验结果中提示。

验收标准：

- 至少完成 Greenhouse、Parcel、Plant、Sensor、Device、Camera 六类对象绑定。
- 从 3D 点选到业务详情的链路可用。
- 从业务列表定位到 3D 对象的链路可用。
- ValidatorAgent 能识别缺业务绑定、缺数据绑定和缺资产元数据的对象。

### 5.3 状态同步与时序记忆

需求：

- 定义对象同步频率：realtime、hourly、daily、milestone、static。
- 支持指标字典：温度、湿度、土壤水分、CO2、光照、pH、EC、水压、流量、设备开关状态等。
- 支持最新值、历史曲线、聚合统计和日级归档。
- 支持事件层：灌溉、施肥、告警、巡检、维护、Agent 分析记录。
- 支持对象维度查询最近 N 天趋势和事件。

验收标准：

- 温室环境、地块墒情、灌溉设备和摄像头在线状态可按对象查询。
- 至少支持 24 小时和 7 天两个时间范围。
- 生成一份温室日报时，能引用同一温室的环境、设备、告警和事件数据。

### 5.4 多 Agent 编排

推荐 Agent 划分：

| Agent | 职责 |
| --- | --- |
| FarmTwinOrchestrator | 接收用户目标，拆解任务，组织 handoff |
| ScenePlannerAgent | 自然语言转对象清单、空间关系和 ScenePlan |
| AssetFidelityAgent | 决定已有资产、F2DMAS、TRELLIS.2、程序化生成或占位 |
| LayoutAgent | 求解坐标、朝向、行列/网格/沿路布局 |
| DataBindingAgent | 绑定业务对象、设备、指标和场景对象 |
| TimeSeriesAgent | 查询和聚合时序数据 |
| GrowthAnalysisAgent | 生成长势评分、胁迫风险和建议 |
| AlertDiagnosisAgent | 解释告警原因、影响对象和建议动作 |
| ReportAgent | 生成日报/周报 |
| ValidatorAgent | 校验缺模型、缺绑定、缺元数据、冲突和风险 |

工具白名单：

- 只读：`scene.current`、`model.search`、`model.metadata`、`object.lookup`、`object.relations`、`timeseries.query`、`event.query`。
- 受控写：`scene.plan`、`layout.solve`、`scene.applyPlan`、`asset.job.create`、`object.bind`、`alert.acknowledge`。
- 禁止：任意 shell、任意文件系统写入、任意 HTTP、直接数据库写入、未经状态机的设备控制。

验收标准：

- Agent trace 记录 taskId、userGoal、mode、步骤、工具、状态、耗时、输入输出摘要、失败原因和回退路径。
- 语义搭建、资产路由、对象绑定和校验至少各有一个可展示 trace。
- LLM 未配置或调用失败时，核心场景搭建仍能走确定性回退。

### 5.5 多保真资产池

需求：

- 每个资产必须有 `assetKey`、分类、来源、许可、保真度、缩略图、GLB 地址、适用对象、质量信息和版本信息。
- 关键植株支持几何版本：苗期、营养生长期、开花期、结果期、成熟期。
- 支持资产入库验收：Three.js 可加载、坐标轴/单位/中心点正常、面数/贴图/体积在阈值内、有缩略图、有来源和许可。
- 支持资产策略：
  - 关键植株、异常植株、论文样本：F2DMAS 或高保真重建。
  - 普通背景植株和大面积作物行：低模实例化和数据缩放。
  - 普通设备和装饰：资产库优先，缺失时 TRELLIS.2。
  - 地块、道路、围栏、沟渠、管线：程序化生成。
  - 缺失资产：占位模型 + 生成任务。

验收标准：

- 资产列表中至少 80% 的公开 GLB 有缩略图和基础元数据。
- 缺失资产能生成任务并关联到场景占位对象。
- AssetFidelityAgent 能为典型温室场景输出资产选择理由。

## 6. 阶段性工作对齐

### 6.1 当前基线

| 能力 | 当前状态 | 下一步判断 |
| --- | --- | --- |
| 3D 场景编辑 | 已有场景编辑、模型加载、地形、图层、模板、保存加载 | 保持稳定，不作为下一阶段主战场 |
| 模型资产 | 数量充足，质量治理不足 | 补元数据、缩略图、来源、许可、LOD |
| IoT/告警 | 模拟链路和基础告警可用，真实接入未充分验收 | 补对象绑定、数据质量和真实设备联调记录 |
| 监控大屏 | 可展示汇总数据 | 补对象钻取、日报归档和告警处置闭环 |
| 业务中心 | 是 6 个子系统完成度总览，不是完整业务系统 | 先补统一业务底座，再拆分子系统 |
| AI 助手 | 只读助手雏形 | 保持只读边界，接入对象/时序/事件工具 |
| SceneBuilderAgent | 已有语义搭建、自动布局、缺失资产占位和 trace | 扩展到对象绑定、资产路由、校验和运维分析 |

### 6.2 推荐里程碑

| 里程碑 | 周期 | 目标 | 主要产出 |
| --- | --- | --- | --- |
| M1：孪生对象底座 | 1-2 周 | 建立农业对象图谱和 3D 绑定 | 对象模型、绑定表、对象详情接口、点选联动 |
| M2：状态与记忆层 | 2-3 周 | 将 IoT、事件、告警和日级归档按对象组织 | 指标字典、时序查询、事件查询、日报数据源 |
| M3：Agent 运维闭环 | 2-3 周 | 扩展 Agent 工具和 trace | ValidatorAgent、ReportAgent、AlertDiagnosisAgent、工具白名单 |
| M4：资产治理与保真度路由 | 2-3 周 | 建多保真资产元数据和路由 | 资产元数据、缩略图、质量审计、AssetFidelityAgent |
| M5：业务子系统拆分 | 3-4 周 | 在统一底座上拆土壤、气象、灌溉、温室、视频、环境子系统 | 独立页面/接口、历史趋势、告警处置、业务流程 |
| M6：生产化补齐 | 持续 | 补真实设备、安全、权限、测试和部署 | 真实联调、RBAC、操作审计、性能压测、CI/CD |

### 6.3 近期 OpenSpec 候选变更

1. `add-agricultural-object-model`
   - 定义 Farm、Greenhouse、Parcel、CropRow、Plant、Sensor、Device、Camera、Operation、Observation。
   - 增加对象查询和关系查询接口。

2. `bind-scene-objects-to-business-objects`
   - 给 3D 场景对象增加业务对象绑定。
   - 支持点选模型查看业务详情。
   - 支持业务对象定位到 3D 场景对象。

3. `add-farm-memory-layer`
   - 建立日级归档、事件表和 Agent 分析记录。
   - 支持按对象查询最近 N 天趋势和事件。

4. `add-agent-operation-trace`
   - 扩展现有 `agentTrace`。
   - 记录工具输入输出摘要、耗时、失败原因、回退和校验结果。

5. `add-asset-metadata-and-fidelity-routing`
   - 给资产增加保真度、来源、质量、缩略图和适用场景。
   - 增加资产质量审计和保真度路由接口。

推荐先做 1 和 2。没有对象模型和绑定层，后续 Agent、日报、资产路由和业务子系统都会缺少统一锚点。

## 7. 成功指标

### 7.1 产品指标

- 3D 对象业务绑定率：核心演示场景中可观测对象绑定率不低于 90%。
- 数据绑定完整率：核心业务对象至少绑定一个实时或日级指标。
- Agent trace 完整率：所有 Agent 任务均有可查询 trace。
- 资产元数据完整率：公开资产基础元数据完整率不低于 80%。
- 缺失资产不中断率：语义搭建中缺 GLB 时能用占位模型继续生成场景。
- 日报生成成功率：温室日报可基于对象、指标、事件和告警生成。

### 7.2 验收指标

- 典型提示词“搭建番茄温室，包含 20 株番茄、气象站、水泵、摄像头和传感器”能生成可加载场景、资产选择理由、布局结果和 trace。
- 点选温室模型能看到温室对象、传感器、设备、指标、告警和事件。
- 点选异常设备能看到最近指标、告警原因和建议动作。
- 对一个完整场景运行校验，能列出缺绑定、缺数据、缺缩略图和缺元数据的问题。
- 生成一份温室日报，内容包含环境摘要、设备状态、告警、灌溉事件和建议。

## 8. 风险与缓解

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 演示能力被误认为生产能力 | 页面丰富但真实设备、权限、控制闭环不足 | 文档和页面标注模拟、真实、待实现状态 |
| 资产数量掩盖质量问题 | GLB 多但缺缩略图、版权、面数和适用标签 | 建资产入库验收和元数据完整率指标 |
| Agent 自动化不可控 | LLM 输出不可解释或误操作 | 工具白名单、预览确认、trace、确定性回退 |
| 真实设备接入滞后 | 只有模拟数据，验收说服力不足 | 优先联调气象站、土壤传感器、灌溉控制器三类设备 |
| 控制闭环安全风险 | 阀门、水泵、风机等直接控制有风险 | 本阶段不让 Agent 直接控制设备，先做状态机、回执和审计 |
| 每日 GLB 重建成本过高 | 植株几何变化频繁但重建慢 | 采用阶段性几何更新和高频状态同步 |
| 业务子系统过早拆分 | 每个系统重复建对象、指标和告警 | 先统一业务对象、指标字典、时序和事件底座 |

## 9. 待确认问题

1. 首个 MVP 场景是否固定为“番茄温室”，还是同时保留“综合农业园区”和“智慧示范田”？
2. 真实设备联调优先级是否确定为气象站、土壤传感器、灌溉控制器？
3. 关键植株高保真重建是否已有 F2DMAS 输出样本和采集规范？
4. 是否需要在下一阶段引入正式登录、RBAC 和操作审计，还是先用演示级用户标识？
5. 日报优先做温室日报、园区日报，还是告警处置报告？
6. 资产元数据来源和许可证是否需要满足正式交付审计，还是先满足内部演示和论文验证？

## 10. 结论

下一阶段的主线应从“展示型 3D 平台”转向“对象驱动的农业数字孪生底座”。最小闭环是：

```text
农业业务对象
  -> 绑定 3D 场景对象
  -> 绑定设备、指标、事件和资产版本
  -> 支持状态同步和历史查询
  -> Agent 基于对象执行搭建、校验、诊断和报告
  -> 资产按业务价值进行多保真调度
```

这个路线能同时对齐工程交付、演示汇报和论文创新点：多保真农业 GLB 资产调度、阶段性几何更新 + 高频状态同步、可追溯多 Agent 农业数字孪生工具链。
